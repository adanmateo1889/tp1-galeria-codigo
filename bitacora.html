Proceso de desarrollo

Diario de la exposición

En esta bitácora registramos las principales decisiones, cambios y problemas que fueron apareciendo durante el desarrollo de Galería Código. La idea es mostrar cómo fue evolucionando el proyecto desde la propuesta inicial hasta la versión final.

01

Idea inicial

Elegimos una galería de arte

Cuando empezamos el trabajo decidimos que no queríamos hacer solamente una página con los perfiles de los cinco integrantes. Buscamos una idea que nos permitiera presentar la información de una forma más original y finalmente elegimos crear una galería de arte virtual.

La propuesta fue representar a cada integrante como si fuera una obra dentro de un museo. Cada perfil tendría su propio retrato, información personal, gustos, habilidades y una pequeña interacción.

02

Primera versión

Armamos la estructura general

Primero creamos una base común para todo el sitio. Se armó una página principal con la colección de obras, una página para cada integrante, la bitácora y las carpetas necesarias para organizar estilos, imágenes, JavaScript y documentación.

HTML: portada, perfiles individuales y bitácora.
Archivos compartidos: una hoja de estilos general y archivos JavaScript para las interacciones.
03

Organización

Dividimos el trabajo utilizando GitHub

Para trabajar entre todos usamos GitHub y GitHub Desktop. Cada integrante fue trabajando principalmente sobre su propia rama para evitar modificar directamente el trabajo de los demás.

Cuando un perfil estaba listo, revisábamos los cambios y luego los incorporábamos a la rama principal mediante Pull Requests.

Decisión: trabajar con ramas individuales.
Motivo: poder identificar los aportes de cada integrante y evitar sobrescribir cambios de otros compañeros.
04

Perfiles

Cada integrante empezó a completar su obra

A partir de la estructura inicial cada integrante fue completando su página personal. Se agregaron los datos de cada perfil, preferencias, habilidades y las imágenes que funcionan como retratos dentro de la exposición.

También tuvimos que actualizar algunos nombres de archivos y los enlaces entre las distintas páginas para que la navegación siguiera funcionando correctamente.

05

Diseño

Ajustamos los retratos y la presentación

Uno de los problemas que apareció fue que las imágenes de los integrantes tenían tamaños y proporciones diferentes. Esto hacía que algunos cuadros ocuparan más espacio que otros y la galería perdiera uniformidad.

Problema: los retratos no tenían el mismo tamaño visual.
Solución: ajustamos los estilos para mantener una presentación pareja entre todas las obras.

También revisamos márgenes, textos y distribución para mantener una estética similar a la de una sala de museo.

06

JavaScript

Agregamos interacción a las obras

Para sumar interactividad incorporamos el botón “Encender foco de obra” en los perfiles. Al utilizarlo cambia la iluminación de la sala y se destaca visualmente el retrato.

Durante el desarrollo evaluamos otras ideas, como agregar juegos o una audioguía textual, pero finalmente decidimos no incluirlas. Preferimos que la interacción fuera sencilla y estuviera relacionada directamente con la idea de una exposición.

07

Responsive

Revisamos el sitio en distintos tamaños

También fuimos probando la galería en distintos tamaños de pantalla. Para eso utilizamos media queries que permiten reorganizar los elementos cuando el ancho disponible disminuye.

El objetivo fue que la portada, la colección y los perfiles pudieran seguir utilizándose tanto desde una computadora como desde pantallas más pequeñas.

08

Integración

Fuimos incorporando los perfiles a la rama principal

A medida que cada integrante terminaba su parte, revisamos los commits y los archivos modificados antes de incorporarlos a main.

Este proceso nos permitió ver en la práctica cómo funcionan las ramas, los commits y los Pull Requests dentro de un proyecto compartido.

Revisión: comprobamos qué archivos modificaba cada rama antes de hacer el merge.
Resultado: los perfiles quedaron integrados dentro del mismo proyecto manteniendo un historial de cambios.
09

Estado actual

La galería está casi terminada

Actualmente ya se encuentran incorporados la página principal, los perfiles individuales, la navegación, la bitácora, los estilos compartidos y las interacciones principales.

La mayoría de los retratos también están cargados. Como último ajuste nos queda incorporar la imagen definitiva del perfil de Fernando y realizar una revisión general de enlaces, imágenes, botones y comportamiento responsive antes de la entrega.

10

Cierre

Lo que aprendimos durante el proyecto

Además de seguir practicando HTML, CSS y JavaScript, este trabajo nos permitió tener una primera experiencia más concreta de desarrollo web en equipo.

Durante el proyecto tuvimos que organizar archivos, trabajar con distintas ramas, revisar cambios de otros integrantes y resolver problemas que aparecieron a medida que la página fue creciendo.

El resultado mantiene la idea que tuvimos al comienzo: presentar nuestros perfiles personales dentro de una galería de arte virtual, combinando diseño, programación y trabajo grupal.
