Proceso de desarrollo

Diario de la exposición

Esta página debe crecer con el proyecto. La idea es registrar hechos reales: qué decidimos, qué problema apareció, quién participó y qué cambio hicimos para resolverlo.

01

Idea inicial

Elegimos una galería de arte

Decidimos alejarnos de una portada tradicional y representar a cada integrante como una obra expuesta. Todos los cuadros mantienen el mismo tamaño para sostener una presentación uniforme, mientras que cada retrato puede inspirarse en una obra o corriente artística diferente.

02

Primera base

Estructura común del sitio

Se creó una portada, cinco páginas de perfiles, la bitácora, una hoja de estilos compartida y archivos JavaScript separados. Los cuatro retratos restantes quedaron como espacios de reemplazo para que cada integrante incorpore luego su propia imagen.

03

Organización

Trabajo del equipo

Completar durante el trabajo: roles iniciales, forma de comunicación, fechas de reunión y distribución de archivos.

Decisión: cada integrante debe realizar commits reales desde su cuenta.
Motivo: el historial de Git debe reflejar el trabajo compartido.
04

Responsive

Pruebas obligatorias

La base incluye breakpoints explícitos en 400 px, 900 px y 1200 px. Antes de entregar se registrarán aquí los problemas detectados en cada ancho y las correcciones realizadas.

05

JavaScript

Interacciones

La portada incorpora iluminación del museo y una visita guiada. Cada perfil tiene una interacción propia: foco de obra, ficha técnica, recomendación aleatoria, cambio de iluminación o audioguía textual.

06

Pendiente

Problemas y cambios reales

Desde este punto deben agregar entradas nuevas con situaciones que realmente ocurran durante el desarrollo. Eviten inventar dificultades sólo para completar la sección.
